# 뉴스 감성분석 모델 — 쉽게 설명하는 발표 자료

## 먼저, 이렇게 이해하면 됩니다

기업 분석 화면에서 시작해 **네이버 API Hub → 우리 서버 → 감성분석 모델 → 분석 화면**으로 이어지는 구조입니다. 모델은 기사를 읽고 **긍정·중립·부정 스티커를 하나씩 붙이는 분류기**라고 생각하면 쉽습니다.

1. **사용자 선택:** 사용자가 기업 검색에서 기업을 선택해 분석 화면에 들어갑니다. 화면은 선택한 기업 이름으로 뉴스 분석을 요청합니다.
2. **네이버 API Hub에서 뉴스 수집:** 우리 Node.js 서버가 네이버 API Hub의 뉴스 검색 API에 기업명과 별칭을 보냅니다. 받은 기사 중 언론사·기업 언급·중복 여부를 확인하고 관련 기사만 남깁니다.
3. **허깅페이스 모델로 감성 분류:** 우리 AI 서버에 불러온 **`snunlp/KR-FinBERT-SC`**에 기사의 제목과 요약을 입력합니다. 이 모델은 한국어 금융 문장의 감성을 **긍정·중립·부정 중 하나**로 분류하는 역할을 합니다.
4. **결과를 분석 화면에 표시:** 기사마다 분류 결과를 붙이고, 전체 기사에서 각 감성이 몇 건인지 셉니다. 예를 들어 10건 중 긍정 3건, 중립 5건, 부정 2건이면 30%·50%·20%로 보여줍니다.

이 비율은 **기사 표현의 분포**입니다. 기업 실적 평가, 주가 전망, 종합 리스크 점수와는 다릅니다.

### 약 45초 발표 대본

“사용자가 기업을 검색해 분석 화면에 들어오면, 저희 서버가 네이버 API Hub에서 그 기업의 최신 뉴스를 가져옵니다. 기업과 관련 있는 기사만 선별한 다음, 각 기사의 제목과 요약을 감성분석기에 보냅니다. 감성분석기에는 허깅페이스에 공개된 `KR-FinBERT-SC`를 불러와 사용했습니다. 이 모델은 한국어 금융 뉴스를 긍정·중립·부정으로 분류하는 역할을 합니다. 저희 서비스는 기사별 결과를 모아, 예를 들어 10건 중 긍정 3건·중립 5건·부정 2건이라면 화면에 30%·50%·20%로 보여줍니다. 이는 뉴스 표현의 분포이지 주가 전망이나 기업의 실제 위험 확률은 아닙니다.”

## 심사위원이 물으면 이렇게 답하세요

| 질문 | 쉬운 답변 |
| --- | --- |
| 어떤 모델을 썼나요? | 허깅페이스의 **`snunlp/KR-FinBERT-SC` 한 개**를 불러왔습니다. 여러 감성 모델을 합친 방식은 아닙니다. |
| 허깅페이스에 매번 기사를 보내나요? | 아닙니다. 허깅페이스에서 공개한 모델을 **우리 AI 서버에 로드해 재사용**합니다. 기사 분석 요청은 우리 내부 AI 서버로 보냅니다. |
| 왜 이 모델인가요? | 일반 대화보다 **금융 뉴스·보고서 문장**에 맞춰 학습된 한국어 분류 모델이기 때문입니다. |
| 구조는 어떻게 되나요? | BERT가 문장의 문맥을 읽고 마지막 분류 부분이 긍정·중립·부정 **3개 중 하나**를 고릅니다. 공개 설정상 BERT 인코더는 12층입니다. |
| 여러분이 직접 만든 것은 무엇인가요? | 뉴스 수집·기업 관련성 확인·중복 제거·모델 입력·결과 집계·저장·화면 연결입니다. 공개 모델 자체를 다시 학습한 것은 아닙니다. |
| `score`는 무엇인가요? | 선택된 라벨에 대한 모델 출력값입니다. **정답 확률로 검증된 수치나 기업 위험 점수는 아닙니다.** |
| 정확도 96.3%인가요? | 그 수치는 **모델 제작자의 공개 평가 결과**입니다. 우리 서비스 데이터에서 같은 성능이 나오는지는 별도 검증이 필요합니다. |

## 구현을 자세히 설명해야 할 때

발표에서 “여러 허깅페이스 모델을 조합해 감성분석했다”고 말하면 정확하지 않습니다. **감성 분류에 쓰는 허깅페이스 모델은 한 개**입니다. 자체 구현한 뉴스 선별·중복 제거·배치 처리·집계 로직과 결합했고, 종합 리스크 평가용 LLM은 별도의 단계입니다.

## 어떤 모델인가요?

- **모델 ID:** [`snunlp/KR-FinBERT-SC`](https://huggingface.co/snunlp/KR-FinBert-SC). 서버 설정 `SENTIMENT_MODEL_NAME`에 지정되어 있습니다.
- **출처와 학습 방향:** 서울대학교 언어학 관련 연구진이 공개한 한국어 금융 도메인 모델입니다. [모델 카드](https://huggingface.co/snunlp/KR-FinBert-SC)에 따르면 KR-BERT-MEDIUM 계열 데이터를 확장하고 금융 뉴스와 애널리스트 보고서를 추가해 금융 문장에 적응시킨 KR-FinBERT를, 감성 분류용 라벨 데이터로 미세조정한 모델입니다. 모델 카드에는 금융 관련 뉴스 제목·본문 **440,067건**, 애널리스트 보고서 **11,237건**을 추가한 것으로 설명합니다. **이 사전학습과 미세조정은 모델 제작자가 수행**했으며 우리 프로젝트에서 다시 학습한 것은 아닙니다.
- **모델 구조:** [공개 설정 파일](https://huggingface.co/snunlp/KR-FinBert-SC/blob/main/config.json)상 `BertForSequenceClassification`입니다. BERT 인코더 12층, 어텐션 헤드 12개, 은닉 차원 768, 최대 위치 512개를 사용하고, 문장 분류 헤드가 세 라벨 중 하나를 선택합니다.
- **출력 라벨:** `negative(0)`, `neutral(1)`, `positive(2)`입니다. 서비스에서는 최종 라벨을 `negative/neutral/positive`로 통일합니다.
- **공개 성능 수치:** 모델 카드에는 5만 건의 라벨 데이터를 사용한 평가에서 정확도 0.963이 적혀 있습니다. **제작자가 제시한 평가 수치이지, 우리 뉴스 수집 환경에서 직접 검증한 정확도가 아닙니다.** 발표에서 현재 서비스의 정확도가 96.3%라고 단정하면 안 됩니다.

## 실제 서비스의 처리 순서

1. Node.js 서버가 네이버 뉴스 검색 API에서 회사명과 별칭으로 최신 기사를 찾습니다.
2. 허용된 언론사만 남기고, 기사 **제목+요약**에 회사명·별칭이 합계 2회 이상 언급된 기사만 선별합니다. 원문 링크 등을 기준으로 중복을 제거하고 최신순 최대 100건을 사용합니다.
3. HTML 표시를 정리한 뒤 기사마다 `제목. 요약` 문자열을 만듭니다. **본문 전체를 읽는 구조가 아닙니다.**
4. Node.js가 문자열 배열을 내부 FastAPI의 `POST /api/ai/sentiment`에 전달합니다.
5. FastAPI가 Hugging Face `pipeline("text-classification", model="snunlp/KR-FinBERT-SC")`으로 추론합니다. 긴 입력은 **최대 512 토큰**으로 잘리고, 기본 **8건씩 배치** 처리합니다. 같은 텍스트의 결과는 프로세스 내 캐시에서 재사용합니다.
6. 입력 순서대로 기사별 `{label, score}`를 돌려줍니다. `score`는 **선택된 감성 라벨에 대한 모델의 출력 신뢰도**이며, 실제 사실일 확률·기업 위험도·감성 강도를 뜻하지 않습니다.
7. Node.js가 각 기사에 결과를 붙이고 긍정·중립·부정 건수를 집계합니다. 각각의 비율을 100분율로 바꾸어 “감성 분석 요약”에 표시하고, 기사별 결과는 `NEWS_ARTICLE_ANALYSIS`에도 기록합니다.

### 입출력 예시 — 실제 기사 분석 결과가 아닌 설명용

```json
요청: {"texts": ["A기업, 신규 계약 체결. 수주 확대 기대", "A기업, 생산 차질 발생. 납기 지연 우려"]}
응답: {"results": [{"label": "positive", "score": 0.91}, {"label": "negative", "score": 0.87}]}
```

예를 들어 선별된 기사 10건이 긍정 3건, 중립 5건, 부정 2건이라면 화면에는 긍정 30%, 중립 50%, 부정 20%로 나타납니다. 이 백분율은 **기사 건수의 분포**입니다. 종합 리스크 점수나 주가 상승·하락 확률이 아닙니다.

## 화면의 다른 AI 결과와 어떻게 다른가요?

| 기능 | 무엇을 하나요? | 모델/계산 주체 |
| --- | --- | --- |
| 감성 분석 요약 | 기사마다 긍정·중립·부정을 분류하고 비율 집계 | KR-FinBERT-SC + Node.js 집계 |
| 기사 정서 지표 | 최근 30일의 부정 기사 비율에 분류 신뢰도와 표본 수 보정을 적용 | Node.js 산식 |
| 분석 결과 문장·이슈 영향도 | 기사 근거를 읽고 사업 영향과 설명을 생성 | 별도의 LLM 평가 단계 |
| 종합 리스크 점수 | 이슈 영향도·기사 정서·보도 확산·보도 지속에 가중치 적용 | Node.js 산식 |

감성 분석 요약은 검색 결과 중 선별된 **최신 최대 100건의 비율**인 반면, 종합 리스크 계산에는 그중 **최근 30일에 해당하는 기사**와 과거 뉴스 이력이 사용됩니다. 그러므로 감성 분포의 ‘부정 %’가 기사 정서 지표 점수 또는 종합 리스크 점수와 일치할 필요는 없습니다.

## 질문 대비: 한계와 정확한 표현

- **자체 개발 모델인가요?** 아니요. 공개된 사전학습·미세조정 모델을 불러와서, 서비스의 수집·선별·배치 추론·집계·저장 파이프라인에 통합했습니다.
- **다른 허깅페이스 모델도 조합했나요?** 감성분석에는 조합하지 않았습니다. 다른 기능에서 사용하는 임베딩 모델이나 생성형 LLM을 감성분류 모델과 혼동하지 않도록 합니다.
- **모델 점수 0.91은 무엇인가요?** 선택된 라벨에 대한 분류 출력값입니다. 정답일 확률로 보정되었다는 증거가 없으므로 “91% 정확하다” 또는 “위험도 91점”이라고 설명하지 않습니다.
- **한계는 무엇인가요?** 제목·요약만 입력하므로 본문 맥락이 빠질 수 있고, 512 토큰을 넘는 뒷부분은 잘립니다. 한 기사에 호재와 악재가 함께 있거나 인용·반어가 있으면 단일 라벨이 내용을 단순화할 수 있습니다. 공개 모델 카드의 성능은 우리 서비스에서 별도로 재현·검증하지 않았습니다.

## 구현 근거

- `backend/ai-server/app/models/sentiment_model.py`: 모델 선택, 로딩, 배치 추론, 라벨 정규화, 캐시
- `backend/ai-server/app/api/sentiment.py`: 감성분석 API 입출력
- `backend/server/src/services/naverNews.service.js`: 뉴스 수집·선별·입력 텍스트 구성
- `backend/server/src/services/newsAnalysis.service.js`: 기사별 결과 결합·분포 집계
- `backend/server/src/services/newsHistory.service.js`: 기사별 분석 결과 저장
- `backend/server/src/services/companyRiskAssessment.service.js`: 기사 정서 지표와 종합 리스크 산식
